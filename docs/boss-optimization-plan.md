# Boss 分批优化执行计划

目标：无人值守完成 16 个 Boss 的机制优化、正式波次接入、可读反馈与自动化回归。设计以当前本地代码为依据，不安装新依赖、不改动用户已有 README/封面/上传脚本，不发布远程版本。

## 批次与验收

| 批次 | 范围 | 工作与验收 |
| --- | --- | --- |
| 1 | 共用规则 | 可测试的预警/执行/恢复状态机、阶段不可逆、真实且有上限的玩家减速、范围逃离时间、召唤归属和总量预算。验证回血不退阶段、控制能结束、攻击有预警。 |
| 2 | 司令、猎手、堡垒、棱镜、磁轨、折线龙 | 护卫保护与破防、冲刺恢复、核心开放、固定锁定图案、射线诱导、巡航路线。逐项测试锁定快照、恢复增伤、护卫清除收益。 |
| 3 | 蜂巢、收藏家、血月锻炉 | 可拆生产节点、可追回资金的搬运单位、可阻止献祭和过热窗口。验证拆节点取消效果、退款一次、预算和生命上限。 |
| 4 | 冰环、蛛后、迷宫、梦魇花 | 可打断冰封、可清理蛛网、可破坏实体墙和持续污染节点。验证阻挡/出口、节点清除后的地形回收、持续区域生命周期。 |
| 5 | 双子、指挥家、星图 | 独立狂暴招式、统一节拍、范围内有预警的位移。验证双实体各阶级、联合攻击协调、节拍与位移范围。 |
| 6 | 统一验证 | 固定随机种子运行所有 Boss、34 波模板、战斗/结算整合与 30/60Hz 行为；测试、构建、浏览器烟测、差异审查。保存机器可读验证报告。 |

每批先确定行为规格，再实现引擎公开接口并测试真实状态变化；不以源码字符串或“能调用”作为机制验收。共用纯引擎接口被正式游戏和模拟器共同调用，防止测试只验证另一套实现。

## 进度

- 批次 1：完成。共用调度、阶段不可逆、减速与保护期、范围预警、召唤预算均接入正式游戏与纯引擎测试。
- 批次 2：完成。护卫保护、冲刺蓄力/恢复、堡垒核心、固定镜步、磁轨诱导及可拆锁标、龙巡航/俯冲。
- 批次 3：完成。可拆孵化巢、一次性资金退款/逃走规则、标记祭品与献祭打断。
- 批次 4：完成。冰封印、蛛网结点、真实墙体与出口、有限扩散污染根，以及对应地形清理。
- 批次 5：完成。双子独奏招式、遭遇主攻击协调、指挥家阶段节拍、范围内有上限的引力。
- 批次 6：完成。128 项测试通过、生产构建通过、112 次固定种子模拟、34 波配置/机制/赏金/奖励回归通过。浏览器验证蜂巢与迷宫、HUD、预警和恢复表现；控制台未记录错误。390×844 视口下 Boss HUD 宽度 340，左右边界 25/365，处于视口内；未把桌面仿真视作真实触摸验收。

## 交付记录

- `docs/boss-optimization-results.md`：每个 Boss 的原设计评价、改进理由、实现和数值。
- `docs/boss-validation-report.json`：96 次阶段演练和 16 次实际射击探针的机器可读记录。
- `scripts/boss-simulation.mjs`：可复跑的正式引擎模拟器；三个种子、30/60Hz、全部阶段技能覆盖。
- `tests/boss-combat.test.js`、`boss-mechanics.test.js`、`battlefield-rules.test.js`、`boss-simulation.test.js`：状态与行为回归。
- `.tmp/boss-optimization/labyrinth.png`：浏览器验收截图，展示可破坏墙、预警/恢复反馈与深色 Boss HUD。

本轮未提交或推送 Git；README、封面和上传脚本的已有改动保留。

## 边界

自动化用于验证机制正确性、生命周期、可逃离时间和确定性。它不能证明所有玩家均觉得有趣，也不能替代目标手机的真实触摸体验。完整平衡结论必须明确区分机器验证与真人游玩。
