# r04 · 1440×900 相机尺度比较

**建议：将 1.25 倍列为桌面候选，待主审选择后再实现。当前产品相机、输入和玩法均未改动。**

打开 [交互对比页](comparison.html)，在同一场景内切换原尺度和 1.25 倍；可切换至原始像素查看。权威证据目录为 `comparison-final/`，四组截图均为 1440×900、DPR 1 的真实 Canvas 重绘。

## 观察与代价

| 项目 | 原尺度 | 1.25 倍 |
| --- | --- | --- |
| 可见世界尺寸 | 1440×900 | 1152×720 |
| 可见世界面积 | 100% | 64% |
| 密集场景首个 FAST 的保守身体边界 | 17.36×15.15px | 21.71×18.94px |
| SPLINTER 的保守身体边界 | 7.47×11.70px | 9.33×14.62px |
| 正常场景身体边界完整落在视口的数量 | 9/9 | 8/9 |
| 密集场景身体边界完整落在视口的数量 | 48/48 | 48/48 |
| 密集场景身体边界完整落在 HUD 下缘至建造栏上缘区间的数量 | 48/48 | 47/48 |

1.25 倍让脸部、器官和外轮廓更易辨认；所有世界内容（角色、描边、危险区、血条、飘字）一起放大，HUD 与建造栏保持原尺寸。角色间相对重叠并不会因此消失。最小 SPLINTER 的身体宽度仍不足 10px，仍需依靠小尺寸轮廓设计。危险区更容易被 HUD 覆盖，原尺度正常场景中的右侧敌人也因缩小视野而部分出界。

边界来自公开 `getCharacterAnchors`，是保守包围盒，不是可见像素测量。HUD 下缘至建造栏上缘是全宽保守区间，不等于实际遮挡蒙版，也未统计角色彼此遮挡。48 个活跃角色包含重复身份，并非 48 种身份覆盖。SPLINTER 实际碰撞直径为 10 世界单位，屏幕直径从 10px 到 12.5px；不要把约 7.5px 的身体宽度当成碰撞直径。

## 四组场景及来源

1. **正常波次**：原 `initGame`、固定 seed 20261002，初始资金 45，经真实鼠标建造两座 BASIC，剩余 15；原引擎推进 600 帧，共 10 秒。6 敌人、2 塔、2 子弹；无限资金和无限生命均关闭。
2. **密集试验场**：既有 Debug GUI 的 Balanced 预设创建 6 塔，实际拖放 HIVE、FROST_JUDGE 和 39 个普通敌人。原引擎推进至 1.1 秒，清除初始出生粒子爆发；41 敌人、6 塔。只通过 CSS 隐藏 DebugSpawnPanel，HUD 保留 TEST FIELD 和无限资源标记。该组不冒充正常关卡。
3. **真实危险区**：继续上述遭遇，推进至引擎实际产生危险区的 2.35 秒；40 敌人、4 塔、1 危险区。没有注入危险区。
4. **微小分裂体**：既有 Debug GUI 实际拖放 SHARD，由玩家原攻击击杀后，原 `deathSpawn` 产生 3 个 SPLINTER；1.5667 秒。用于微小轮廓观察，不代表正常密集波次。

## 同场景保证与限制

- 固定源快照包含当时已注册的全部 48 个资源；879 个文件，捕获期间零变化。SCOUT 中间帧与 SENTINEL 脚部可能仍处于其他所有者的局部返修，本次不是最终角色验收。
- 使用已批准的 DEV `reset/step/snapshot` 桥接原引擎，场景实体通过真实 GUI 创建；无任意状态 setter。
- 浏览器内临时包装 Canvas 顶层世界变换，围绕视口中心执行统一 1.25 倍向量重绘；没有编辑截图或缩放成品位图，没有写入产品源码。
- 每张截图后，对桥接返回的完整 semantic 对象执行深比较；四组 `worldUnchanged` 与 `uiRectanglesUnchanged` 均通过，每组状态 SHA 见 [原始报告](comparison-final/report.json)。页面、绘制和呈现错误均为空。
- 所有 GUI 操作均在原尺度执行，1.25 倍只用于截图。尚未实现或验证放大后的输入逆变换、拖放、幽灵、射程交互；不作性能或其他桌面尺寸结论。
- 背景仍使用原始视口参数绘制后裁切，可能多绘制屏外图案，本实验不可用于性能比较。
- `comparison/` 是因定位器问题中断的初次运行；`comparison-02/` 是粒子过密且有调试展开按钮残留的中间版本。保留溯源，均已被 `comparison-final/` 替代。

## 主审选择后的实施边界

若选择 1.25 倍，应统一世界变换与输入逆变换：`screen = viewportCenter + zoom × (world − camera)`，`world = camera + (screen − viewportCenter) / zoom`，并统一现有相机震动约定。幽灵、射程、危险区必须使用同一变换，DOM UI 保持屏幕尺寸。不得为了适应缩小后的视野而修改波次、出生位置、碰撞或其他玩法参数。

随后以相同**世界输入**进行行为差分，补三个桌面尺寸、正常密集战场、输入与性能 QA。当前 r04 仅支持选择尺度，不替代独立 96 项玩法差分及全角色验收。

复现脚本：`camera-comparison.mjs`。封存后请传入 r04 之外的新输出目录，避免覆盖证据。封存信息及文件哈希见 `packet.json`、`READY.json`；所有生产所有权文件与 r03 的一致性见 `scope.json`。
