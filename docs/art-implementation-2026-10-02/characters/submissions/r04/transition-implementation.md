# r04 continuous named-part variant sampling

The public rig sampler now supplies a generic morph; no enemyRigData.js edits or new worker fields are needed. For a selected attack/windup/trigger variant, interpolate each shape from the same-id base shape to its approved variant with weight sin(pi*poseProgress)^2. At 0 and 1 it is exactly the base geometry; at .5 it is exactly the authored variant. Interpolate matching local joints with the same weight. Squash/crouch diagnostic snapshots retain the full authored variant. Existing authored shape changes suppress the additional generic whole-body soft scale, avoiding double compression.

Corresponding ellipses interpolate center/radii. Paths convert absolute L/Q to mathematically equivalent cubics and subdivide longer cubic spans by exact de Casteljau until segment counts match. Endpoint source paths remain unchanged. Each source shape id has exactly one rendered shape. A different open/closed outline interpolates only its closing stroke coverage; there is no whole-body crossfade, duplicate eyes or duplicate organs. Numeric intermediate commands are traced directly, so no per-frame Path2D or unbounded path-string cache is created. SVG output serializes the same commands.

This covers FAST/run, SPLINTER/hop, SHIELD/guard, BOMBER/inflate, BEACON/summonWindup/summonTrigger, SCOUT/crouch/chase and SIEGE/strike. FAST foot-left, SIEGE fist-right and BOMBER open cheek-arm outlines use exact curve normalization. SCOUT now uses the accepted enemy r04 data: its four variant leg paths have exact C2 subdivisions, with identical endpoint contours. Opposite closed contour winding is aligned by reversing curve order and control points exactly; this avoids folding a foot inward. The sampler's older four-to-five SCOUT fallback is inactive for this accepted five-cubic data. No exclusive group module is edited by the role owner.

Ellipse-to-path changes on TWINS_SUN interpolate one named eye contour, using an equivalent cubic ellipse at intermediate samples. Fill/stroke coverage changes on that same eye. RAIL_WARLORD recover's near-eye-closed is explicitly aliased to near-eye in the local registry, with its own white highlight and brow suppressed continuously. Undeclared organ additions/removals still fail validation. The renderer never draws two copies of an eye or a whole-body crossfade.

FORTRESS closed/raised shell can use the same mechanism. The separately accepted shapeMorphs data contract supports the author's exact normalized shell topology and attack sin² interpolation. Both mechanisms close at attack endpoints and raise at .5. Connector/body/root/collision center stay unchanged. Boss A remains responsible for its new exclusive data revision; this owner does not edit that file.

The explicit shell contract supplies the final contour once, replacing the generic shape result rather than interpolating it again. The 27-sample eye-and-shell audit verifies each numeric shell command against the contract, SVG decoding and unique organ ids. The raised connector is visible in the nine-frame PNG. Ordinary actor collisions, root positions and projectile origins are unaffected.

All ordinary soft windup and articulated angle weights use sin(pi*progress), matching neutral at both ends and the existing attack endpoint. Decorative sway uses Frame.time rather than a pose-reset clock, preserving phase across pose changes and freezing on paused game time. There is no mutable animation timer or global actor cache to survive a restart. Mid-pose interruption immediately adopts the new actual pose; this explicitly accepted limit can reset deformation abruptly, without lingering old animation. Smooth interruption sidecar blending is not part of this revision.
