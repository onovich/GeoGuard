# 三位受限信息玩家模拟评估

日期：2026-10-01。已完成23局主试、1局原地等待辅助试验。所有24局玩家汇总均与服务器独立审计记录一致。最高到达第9波，完成8波；没有样本通关。停止或900秒预算耗尽不算死亡，也不算胜利。

本轮只新增模拟工具、测试和报告，没有据这些样本调整正式游戏平衡。详细局后数据与会话标识见 [player-playtest-report.json](./player-playtest-report.json)，接口契约见 [player-simulation-api.md](./player-simulation-api.md)。

## 方法与信息边界

三个subagent以独立、无历史上下文启动，分别扮演谨慎新手、阵地经营玩家、移动避险玩家。只允许阅读玩家接口说明、自己当前及历史公开观察、自己的结果。不得阅读源码、配置、未来波次、其他玩家报告或服务器审计。复查三个客户端未发现导入游戏模块；这仍是协作协议，不是操作系统级隔离。

服务器从正式第一波开始：100血、45资金，正常敌人、伤害、掉落、建造和奖励逻辑。复用正式运行模块，不强制Boss阶段、不加血、不改资金。每次操作推进固定60Hz物理步，移动持续执行时没有中途观察或自动躲避；三种身份最短反应间隔为0.7/0.4/0.3秒。建造需原地占用1.2/0.9/1.1秒，失败也消耗时间。

观察只包含HUD、当前可见实体、裁剪到视口的预警几何和画面可见蓄力进度。Boss全局血条和反制文案可见，屏外位置、技能倒计时、敌人伤害/速度、未来生成、水晶价值不可查询。局后仪表仅在结束后开放。反馈来自血量变化、可见对象变化、操作成功/失败、推进记录和局后损塔/经济统计。

这是一种低成本的语义画面模拟：准确识别目标和几何，不模拟阅读耗时、视觉遮挡、听觉、手指误触或真人情绪。建造暂停移动是实验假设，未验证浏览器中的多输入操作。无渲染循环也不能代替真实浏览器集成测试。

## 主要结果

| 玩家 | 局数 | 代表结果 | 解读 |
| --- | --- | --- | --- |
| 谨慎新手 | 8主试+1辅助 | 初次A在54.1秒第一波死亡；调整后A/C完成2波，在第三波死亡；B存活900秒仍第一波 | 提示能促进学习，但理解与执行反制仍不足；生存与推进可以脱节 |
| 阵地经营 | 6 | A/B完成8波，第9波死亡；C修正线段避险后仍第3波死亡 | 经营策略可以显著推进；不是所有失败都源于缺钱 |
| 移动避险 | 9 | 修正后A/B/C和桌面对照均第一波无伤，但900秒都停在第三波 | 预警存在可执行的避让方法；长期避险可能放弃输出和接战 |

这些不是三种真人群体的胜率：策略版本在学习、样本使用重复种子，且控制器能力不等。不能用“没有通关”断言游戏无法通关。

### 1. 重新接战引导是最值得优先验证的体验方向

多位玩家观察到局部没有敌人、塔和水晶，Boss HUD仍持续提示蓄力/恢复；移动玩家A初版900秒仍第一波，修正版多局停第三波。玩家可以避免死亡，却没有形成“逃离危险—回到输出范围”的闭环。

建议首先做屏外Boss方向提示、长时间无有效输出的轻量提示，说明恢复期应回到射程。提示只给方向与当前战斗目标，不揭示隐藏技能。再测试有空间记忆的搜索策略，以区分引导缺失和控制器绕圈。当前证据不支持称为游戏卡死。

### 2. 第三波的阵地恢复能力需要专项对照

新手v3 A/C分别损失23/23、19/19座塔，结束仅余6/10资金；移动v3 A/C分别损失22/22、26/26座塔。阵地C修正线段避险后第一波剩99血，仍于172.4秒第三波死亡，损塔15/16。

这是需要研究的压力节点，但这些玩家常在身边密集造基础塔，没有充分执行HUD的分散塔阵、恢复期输出，也没有使用已解锁的反制塔。建议固定同一随机场景，对比密集/分散布局、基础/混合塔阵、主动回到射程/持续逃离，记录第三波耗时、损塔、补建成本和可用资金；证实正确反制仍无法恢复后，再考虑耐久、摧塔频率或恢复经济。

### 3. 奖励到策略的转化不足

多个客户端选择链锯塔、迫击塔等解锁后仍只造基础塔；移动玩家始终取第一张奖励。这让解锁收益没有进入实战，也使经济和塔强度评价失真。

值得测试解锁后的用途说明、首次建造提示、对应Boss反制关联。下一轮控制器应依据公开塔说明使用混合阵容；本轮不能据此认定新塔无用或解锁奖励偏弱。

### 4. 暂不全面下调预警伤害或提高资金

早期三个控制器都不同程度地把线状危险区当圆形或只避让起点。移动策略改用线段距离后，四局第一波都100血通过，说明至少在0.3秒语义反应模型中存在可行避让方法。新手最后版本仍未正确计算线段距离，不能据其伤害断言0.7秒反应窗口不足。

阵地A/B第9波死亡时仍剩312/326资金，建塔70/81座、损塔65/68座；更像输出、布局、奖励和危险处理共同问题，而不是普遍现金不足。伤害仪表累计的是实际收到的事件伤害，可包含恢复后的伤害及致死溢出，不应把大于100的累计值当作额外生命。

### 5. 手机问题仍需真实触控验证

同一移动v3策略、A场景、相同反应与建造时间，手机390×844和桌面1280×800均停第三波、剩80血；前两波完成时间分别45.6/80.6秒和56.3/96.1秒。本组对照没有显示普遍手机劣势。视口会改变生成位置、可见目标与基于边缘的策略，因此不是纯粹的屏幕宽度因果实验；精确语义几何也掩盖了识图难度。

## 高速交互与复用

在项目目录运行 `npm run simulate:players`，服务仅监听 `127.0.0.1:5181`。按接口文档通过Node内置fetch调用 `/create`、`/observe`、`/act`、`/debrief`，无需浏览器渲染和额外依赖。subagent可先编写观察→决策→行动循环高速试验，再查看自己局后结果调整策略；不要用逐条模型工具调用代替每帧控制。

23局主试累计推进13,324.6模拟秒，核心推进耗时4,786.6毫秒，约2,784模拟秒/计算秒。该数字不含HTTP序列化、策略计算和模型思考，不能视为端到端运行速度。固定场景和分离的随机序列允许复验；新手A/v2重复结果一致。

完整原始反馈和动作证据保存在 `.tmp/player-playtest/`，三个玩家客户端在其 `clients/` 子目录，服务器独立记录在 `audit/`。客户端是本轮迭代实验产物，部分版本读取既有自己的结果后追加，不保证直接重跑等价于从头重现全部历史版本。报告记录最终客户端和接口的SHA-256；服务器审计可验证历史会话。

`npm run report:players` 在原始记录仍存在时重新核对全部局后汇总并生成精简JSON报告。后续每轮应保存独立策略版本，固定场景先作成对对照，再扩大随机样本；真实UI小规模试玩负责验证语义接口无法覆盖的体验。本轮只覆盖到第9波，不能评价所有16种Boss与终局平衡。
