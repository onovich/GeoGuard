# GeoGuard 受限玩家模拟 API v1

此文档是试玩 subagent 唯一可以读取的项目说明。不要读取源码、引擎数据、模拟器实现、其他玩家文件或审计报告。像玩家一样从自己的观察学习；不要由项目文件获得敌人伤害、冷却、未来波次、隐藏位置或随机数。

服务：`http://127.0.0.1:5181`，四个 JSON POST 接口。每局从正式第 1 波开始，正常血量、初始资金与蓝图，没有调试功能。时间只在合法行动时推进，以固定 60Hz 执行；不必等待真实时间。调用 `observe` 不推进时间，但不能越过行动间隔得到新的战斗信息。

## 建立一局

```js
const post = async (path, body) => {
  const response = await fetch('http://127.0.0.1:5181' + path, {
    method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify(body)
  });
  const result = await response.json();
  if (!response.ok) throw new Error(result.error);
  return result;
};
const start = await post('/create', { profile: 'novice', scenario: 'A' });
const session = start.session;
let observation = start.observation;
```

`profile` 为 `novice`、`builder` 或 `mobile`，使用分配给你的身份。

| 身份 | 最短行动/观察间隔 | 建造占用时间 | 默认视口 |
| --- | --- | --- | --- |
| novice | 0.7 秒 | 1.2 秒 | 1280×800 |
| builder | 0.4 秒 | 0.9 秒 | 1280×800 |
| mobile | 0.3 秒 | 1.1 秒 | 390×844 |

`scenario` A/B/C 为三组固定但不公开内容的随机样本。`viewport` 可选 `default`、`desktop`、`mobile`，供同策略视口对照。每局最多 900 模拟秒，达到上限不等于胜利。

## 玩家观察

返回 HUD 的血量、资金、时间、当前波次、已解锁塔及工具提示属性、奖励卡、Boss HUD。只返回当前视口内的敌人/机制实体、塔、水晶和危险区；所有坐标是屏幕像素，角色坐标不总在正中，因镜头会缓动。普通敌人没有伤害、速度、内部类型或技能配置；可以依据颜色、透明度、护盾和相邻观察间的位移判断。追踪标识 `uid` 仅供记住见过的对象，不能用于查询对象。

水晶不公开数值。危险区有几何形状和可见预警进度 `charge`（0→1），没有精确倒计时、伤害、后续脉冲或所属 Boss 内部数据。`windups` 是画面可见的 Boss 锁定线，尚不公开将使用哪一招。线段裁剪到视口边界。Boss 的血条/阶段/反制提示和正常游戏 HUD 一样全局可见，但不公开屏幕外的 Boss 位置。

这是语义化画面接口：无需识图、位置较准确，不模拟 UI 遮挡、触控误差、阅读耗时和听觉。不可据此宣称验证了真人感受或手机触摸手感。信息限制由 API 响应白名单和玩家操作协议实现；subagent 仍有文件工具，因此本轮还依赖不读其他文件的协作约束，并非操作系统安全沙箱。

## 行动

```js
const result = await post('/act', { session, action: {
  type: 'move', move: { x: 1, y: 0 }, seconds: 0.7
}});
observation = result.observation;
```

- `move`：x/y 范围 -1～1，长度超过 1 会归一化；可慢走。按此方向持续移动，自动射击。秒数范围为身份最短间隔至 3 秒。行动期间没有中途观察或自动躲避。
- `wait`：原地停留同样的时间约束，自动射击。
- `build`：`{type:'build',towerId:'BASIC',x:700,y:460}`。只能造已解锁且付得起的塔；先原地度过建造时间，再在该屏幕位置尝试放置，失败也消耗时间。不能放在屏幕外或底部 130 像素建造栏区；与玩家/塔/敌人重叠会失败。只能一次造一座，不能同时走位。没有右键升级、卖塔或调试建造。
- `reward`：`{type:'reward',index:0}`。只能选择返回的奖励卡；奖励期间战斗冻结。选择后开始下一波。
- `stop`：结束当前局、获取评估记录。不要把主动停止算死亡或通关。

只有上述操作合法，不支持直接伤害、传送、查询隐藏状态、改变种子、强制阶段、读未来波次或改动经济。

`feedback` 提供建造是否成功、重叠/资金不足等操作反馈。`observation.events` 是近期可见的建造、Boss 到来、奖励和换波消息；伤害通过玩家血量/血条变化判断。

## 结束与反馈

死亡/时间上限/主动停止后，响应包含 `debrief`；也可 POST `/debrief` 携带 session。存活中不能获取汇总。汇总是测试仪表提供的局后数据，包含推进、塔损失、资金拾取、伤害类别、运行速度，不能在同一局中利用它做决定。不是玩家常规 HUD。

可以在你自己的 `.tmp/player-playtest/clients/<身份>.mjs` 中编写观察→决策→行动循环，使用 Node 内置 fetch，无需安装依赖。允许循环高速运行，但决策只依赖当前/之前的公开观察和自己先前的经验；不能导入项目模块。每局保存简洁行动摘要与结束汇总到自己目录，不输出完整逐帧观察。需要记录策略版本、为何改变策略、看到的证据，区分策略失败与游戏机制问题。

建议流程：A 的初次体验 → 分析可见失败 → 合理调整 → A 复试 → B/C 泛化。至少五局。长循环需要输出进度，不能在遇到奖励时不选择导致原地无限请求。
