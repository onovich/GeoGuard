# 电脑端视觉还原度审查：UI

2026-10-03。只读审查，没有修改产品文件、游戏逻辑或提交。结论：功能骨架已接入，但玩家 UI 尚不能按原画视觉还原通过。没有发现足以列为 P0 的问题；建议优先修复以下 4 类 P1，再处理 4 类 P2。

## 范围与证据

读取完整画册 HTML、全部 45 张有效图板（8 张联系页逐板看过，名单见 read-scope.json），重点以整图查看 master r04、高密度图、DUI01、DUI03、B05；阅读画册 README、desktop UI r02 production-notes、delivery r02 actual-state-and-limits、effects-ui r02 production-notes 和 ui-color-type-spec。其余角色板仅用于整体风格校准，不宣称在本 UI 审查里对全部 375 动作逐条复核。

本轮独立 IAB tab，1280×720，真实源码页面 http://127.0.0.1:5173/，实际点击、拖放、原生滚动条和键盘焦点。新截图全部在本目录；没有拿上一轮截图代替。覆盖开始、普通 HUD、暂停/恢复、九塔栏首末、说明浮层、建塔成功、资金不足释放、Boss 单成员、测试场双成员、三项升级奖励/蓝图、测试场死亡和普通模式死亡。测试场 UI 遮挡只记录限制，不作为玩家 UI 缺陷。已关闭自己的临时 tab。

局限：浮层截图 07-tooltip 是真实键盘焦点触发的同一说明组件，不冒充纯鼠标 hover；鼠标移入曾在拖放过程中观察到同源浮层，但未单独保存清晰图。native drag 是一次完整拖放，所以本轮没有抓到鼠标仍按下时的 ghost；不能评判所有拖建中间态。奖励为既有 Open Reward 的真实三个升级 choice，不是正常击杀奖励链或 1/2 项奖励。双子使用既有 SpawnCard 拖出，顶部受开发面板遮挡，未把遮挡算缺陷。未测 960×720、1440×900、DPR 2；不宣称所有电脑尺寸均已审查。

## P1：必须修复

### UI-01 开始、暂停、结束都退化成通用小弹窗，品牌与状态语义丢失

原画：production-art-2026-10-02/effects-ui/submissions/r02/b05-start-end.png 的 U01/U02，b07-controls-placement.png 的 U06；字色以 ui-color-type-spec.md 覆盖浅绿白字，不复制图上的白字。

实机：00-start.png、01-pause.png、13-end-normal.png。开始使用「纸张上箭头」蓝图图标，原画是独特叶片标志；结束使用完整爱心，原画是珊瑚破碎图形；三个状态的主按钮都变成同一蜂蜜色，而规格要求开始/继续 sage、重新挑战 coral。标题虽然粗，但视觉上是普通 30px 系统标题，缺少原画的主标题、符号、细分隔与留白层次；面板空白只在内容之间机械排列，没有原画那种完整封面感。起始与失败的状态气质难以区分。

建议：独立设计并接入叶片 logo、破碎结算符号；恢复三种按钮的语义色；做电脑端封面/结算版式，保留系统中文正文字体与动态数据，不裁取生成文字。不要照搬原画的渐变、高光或背景森林；用二维平色、少量外围短线与小地面斑完成强调。开发入口保持现有功能，低优先级。

### UI-02 奖励卡把语义辅色铺成整张卡，原画的奶油底、徽章、图标与 CTA 层次没有还原

原画：dui03-boss-rewards.png D/E/F；b06-rewards-blueprints.png U03/U04。规范要求奶油面板、类型徽、标题、效果、必要 detail、一次 CTA，以及蓝图/心/资源的符号语法。

实机：05-reward.png。三个升级 choice 是真实状态，三个同类型当然允许同色；问题不是「没有凑齐蓝/绿/黄三种」。实际整块 231×348 卡都填成 #B6D4AE，类型只是无底小字，中央图标是很小的纸张箭头，说明用长段落混排，「补贴 / 造价 / 伤害 / 射程 / 间隔」无法快速分组；下方 CTA 是淡奶油而非该类型强调色。DOM 测得卡片 231.3×348，标题 18/24、整体正文字体 16/24；尺寸足够，不需要继续缩字来救排版。绿色面积太重，像通用表单块，缺少原画漂亮的卡面留白。

建议：奶油底＋有色 pill 类型徽＋更清楚的蓝图图标＋底部语义色 CTA；升级只整理动态 detail 的行/组层次、不删字段、不影响未来新建的规则。共用说明只展示一次，CTA 底对齐，集中放大有意义的图标，删除无意义的大色块。先针对三项同类型 case 做美观验收，再补 1/2 项与 mixed case。

### UI-03 单 Boss 中文名被挤成断裂两行，文字信息失去原画的紧凑秩序

原画：dui03-boss-rewards.png A（蜂巢建筑师单成员），master r04 twins 的清楚行结构。文字合同允许换行，不能为了目标高度丢字段；但不意味着每个名字都随意断词。

实机：11-insufficient-release.png 是普通模式真实方阵司令，标题上已经显示一次「方阵司令」，成员行 50px 名字列把同一名字切成「方阵司 / 令」。肖像和血条各占独立列，动作放最右；名字像被误排而不是主动设计。源码 GameHud 证实所有成员统一 grid-cols-[32px_50px_minmax(64px,1fr)_110px_minmax(140px,1fr)]。三、四、六字成员名都用 50px，不是个别截图数字导致。

建议：单 Boss 与双成员分别排版；单 Boss 可让成员名与 phase 上行并列、血条独立整行或右部，对策仍完整。双成员使用可伸缩姓名列或让名称和阶段自然换行，避免单独落一字；不能合并双血条、藏 phase/action/guard。以实际最长中文名和长对策回归，勿仅用曜子/蚀子二字验收。

### UI-04 部分玩家动作文字仍停留在 12px，弱于正式电脑规格

原画/权威：ui-color-type-spec.md 的开始/继续按钮 16px 起；desktop UI production-notes 的正文 14px、动作 14px、辅助 12px目标。

实机：02-normal.png、03-nine-left.png、07-tooltip.png。DOM 确认顶栏暂停为 700 12px/16px，50×36px（不是 16px）；「我知道了」12px/16、66×26。BuildBar 源码及实机确认低资金状态、拖拽建造字为 12px。它们功能可读，但和原画中明确的动作强调相比太小，CTA 视觉重心弱。不要把 HP/phase 的合规 12px 辅助字一起盲目放大。

建议：暂停/继续和关键状态采用明确的 14–16px 动作层级，至少先让暂停到 16px；按钮尺寸相应增加但继续保持紧凑顶部。低资金保留清晰费用与状态，不淡化整卡；可用符号＋14px关键状态。点击范围是否做到44属于另一功能议题，这里仅记录其小体量破坏电脑视觉层次。

## P2：完成上述后再精修

### UI-05 塔卡中性/不足状态太接近，边框淡而统一，标题和内容的视觉关系偏表格

原画：dui01-nine-towers-scroll.png；master density r04。

实机：03-nine-left.png、04-nine-right.png、10-built.png。卡宽 140、间距 8、底栏 920 等结构已经遵循合同，不把这部分误报成尺寸不足。实际标题全部左对齐、次级类型左对齐、灰褐细边统一；原画的更鲜明身份块、居中标题和不足强调在整体中缺少。低资金费用可读符合规范，但状态没有图标，只是一条很弱的浅珊瑚底。

建议：在既有 140px 卡内微调名称、肖像、费用构图；以原画的标签/留白比例而不是 PNG 像素直接反推尺寸。增加不足符号，小范围加强状态边框；不把全部正常卡刷成高饱和红边。角色图标的线粗与形状问题交由角色审查。

### UI-06 hover/focus浮层缺少与所属卡的视觉连接

原画：master density r04 底栏上方说明框、DUI02 A。

实机：07-tooltip.png（同源键盘焦点浮层）。正文14、间距8等基本遵循合同，但是一块漂在上方的普通圆角框，没有原画指向卡的小尾；其位置受 max360 向内夹取，右卡内容浮在前卡之上，靠焦点轮廓才知道属于谁。

建议：轻量尾或一条短连接标记，始终指向当前卡，保持完全 pointer-events-none；不增加详情面板或遮挡中央活动区。

### UI-07 状态 Banner 与键盘教学都用宽奶油矩形，缺少原画的符号语法

原画：B07 U07 状态色徽、U08 WASD/方向键帽；暂停 U06。

实机：10-built.png 的操作提示以及正常重开时观察的「波次来袭1」540px宽框（02-normal / 新 UI 初始观察，10-built 提示保留）。键盘提示是文字＋小按钮，长期落在角色下方，缺少键帽形状，也没有 B07 的波次/阶段不同 tone 的辅助标记。宽框形式和 reward/start 的通用框一样，统一性有了、风格变化没有。

建议：用小键帽和简单阶段符号，状态 Banner 控宽、按 tone 上少量 sage/coral/honey；提示避让当前主体并保持一次关闭。不要加新控制方式、技能条或常驻手机摇杆。

### UI-08 HUD 心/资源/时间及血条的线性重量失衡

原画：整体 r04 和 DUI01 顶栏；颜色以最终 mint/coral 规格为准。

实机：02-normal.png、11-insufficient-release.png。心24px、资源24px、时钟16px，HP只有6px，Boss8px；四个顶部小圆角框的边线和细小内部符号几乎同重量。概念图信息块清楚，实机更像简易细线表头，尤其血条像下划线。不是要求把图上的 cyan 或渐变烤进游戏；当前 mint/coral token 合规。

建议：局部调整图标内线、血条厚度和数字字号，让生命与资金一级、时间二级；状态以少量实心面积提高识别。保留细信息面板与粗角色描边的差别，不把所有 UI 统一描粗。

## 不应误报 / 已做对的部分

保持奶油底、深棕字、9塔横滚、真实卡数、独立血条、完整对策、真实蓝图规则、不足仍可起拖、可读费用。没有要求原画示例资金/波次/等级等于实机。没有把 cyan资源、浅绿白字、渐变高光、森林背景等生成图偏差当正式要求。没有把本地开发测试入口、测试面板遮挡、试玩数据按钮算玩家美术不还原。塔栏真实只有开局三塔属逻辑，应保留，不要求开局九塔。没有功能失败就不制造 P0。

下一轮视觉验收应固定同一桌面尺寸与合法状态，对 B05 开始/结束、DUI03 单成员+三奖、DUI01 九塔首末至少逐项截图比对；本轮只能通过「可用」，不能通过「美观还原」。
